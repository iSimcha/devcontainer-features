# iSimcha dev container features

Shared [dev container features](https://containers.dev/implementors/features/) for iSimcha repositories. They replace
the per-repo copies of the devcontainer install scripts and the Nushell / Starship configuration that previously drifted
between `investigator-db`, `idb-web` and `idb-reports`.

## Features

| Feature | Reference | What it installs |
| --- | --- | --- |
| [dev-shell](src/dev-shell) | `ghcr.io/isimcha/devcontainer-features/dev-shell:1` | Nushell, ouch, and the CLI tools in [packages.json](src/dev-shell/packages.json); lays down the Nushell and Starship configuration |
| [dev-tools](src/dev-tools) | `ghcr.io/isimcha/devcontainer-features/dev-tools:1` | cspell and the Claude Code CLI (npm globals) |

## Usage

```json
"features": {
  "ghcr.io/isimcha/devcontainer-features/dev-shell:1": {},
  "ghcr.io/devcontainers/features/node:1": {},
  "ghcr.io/isimcha/devcontainer-features/dev-tools:1": {}
}
```

`dev-tools` needs npm. Add the `node` feature unless the base image already ships it.

## Adding a CLI tool

Add an entry to [src/dev-shell/packages.json](src/dev-shell/packages.json) and bump the `version` in
[src/dev-shell/devcontainer-feature.json](src/dev-shell/devcontainer-feature.json). Consuming repos pick it up on their
next rebuild, with no change on their side.

Each entry names a GitHub release asset:

- `bin` for an uncompressed binary
- `glob` for a binary inside a compressed archive, unpacked with `ouch`

## What is deliberately NOT here

These stay in [iSimcha/common-files](https://github.com/iSimcha/common-files) and its files-sync action, because a
feature installs into the container and cannot put a file in the consuming repository's working tree:

- `.cspell.json`, `.prettierrc.json`, `justfile`, `.gitignore`, `.vscode/settings.json`, `devcontainer.json`
- `.github/workflows/*`
- `.scripts/secrets/mod.nu`, which the repo `justfile` loads with `use "{{ justfile_directory() }}/.scripts/secrets"`
- `.scripts/export_run_history.nu`, a Cloud Run reporting script carrying environment-specific project ids
- `.devcontainer/install-jdk-jetbrains.nu`, `fix-jetbrains-vmoptions.nu` and `config-devcontainer.sh`, since JetBrains
  Gateway is not a supported client

## Publishing

`.github/workflows/release.yaml` publishes to `ghcr.io` on a push to `main` that touches `src/**`. The published
packages must be **public** so Codespaces and CI can pull them without a registry login. Set that once per package under
the organization's package settings after the first publish.

## Testing

```nu
npm install --global @devcontainers/cli
devcontainer features test --features dev-shell --project-folder .
devcontainer features test --features dev-tools --skip-autogenerated --skip-duplicated --project-folder .
```
